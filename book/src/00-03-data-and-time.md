# 第 0.3 章 文本、JSON、时间与数值

市场数据最初通常是字节和文本。只有经过解析、校验和单位转换后，它才可能成为程序内部可信的价格、数量或事件。本章建立这个边界意识。

> **学习导航**
>
> - 开始前：理解值、函数、条件、循环和错误。
> - 这一章学会：区分原始文本、结构化字段、业务值和事件时间。
> - 大约需要：5–7 小时。
> - 做完留下：原始样本、字段规格、错误样本和数据质量报告。

> **本章层级：必学。** 后面的行情、订单和回测都依赖这里的分层。

## 0.3.1 字节、文本和业务值不是同一层

网络或文件最先提供的是字节。按照字符编码解释后得到文本，再按 JSON 或 CSV 规则解析成字段，最后经过业务校验才成为价格和数量：

```text
bytes -> text -> structured fields -> validated domain values
```

“JSON 能解析”只证明结构语法有效，不证明价格精度、方向、编号顺序或产品规则正确。每一层都应保留自己的错误。

## 0.3.2 JSON 的对象、数组和字段

一条简化行情可能是：

```json
{
  "symbol": "BTC-USDT",
  "sequence": 101,
  "event_time_ms": 1767344400000,
  "bids": [["100.00", "2"]],
  "asks": [["100.01", "3"]]
}
```

解析前要回答：

- 哪些字段必须存在？
- 字符串和数字能否互换？
- 未知字段是忽略、记录还是拒绝？
- `sequence` 的作用域是什么？
- 价格和数量允许多少小数？

这些规则来自具体协议，不应由解析器猜测。

## 0.3.3 时间至少有三个含义

交易系统常见：

- `event_time`：外部系统声称事件发生的时间；
- `receive_time`：本机收到消息的时间；
- `process_time`：本机处理完成的时间。

它们不能互换。两个系统的时钟如果没有校准，`receive_time - event_time` 也不一定是真实单向网络延迟。

时间值还要说明单位和时区。`1767344400` 可能表示秒，`1767344400000` 可能表示毫秒；仅靠数值大小猜测会制造隐蔽错误。

## 0.3.4 为什么金额不能随便使用浮点数

十进制小数通常无法被二进制浮点精确表示。统计分析可以使用浮点，但订单价格、数量和账务值需要明确精度、舍入时点和余数归属。

初学阶段先建立下面的习惯：

```text
"100.05" --按产品规则校验--> 2001 ticks when tick_size = 0.05
```

不要先转成浮点，再四舍五入并假设总能得到正确整数。买价向下舍入、卖价向上舍入等规则也属于业务规格。

## 0.3.5 数据质量不是“能读取文件”

对一小段事件至少检查：

- 文件或消息是否完整；
- 必填字段是否缺失；
- 是否存在重复记录；
- sequence 是否连续；
- 时间是否倒退；
- 价格和数量是否合法；
- 输入采用哪个 schema 和产品规则版本。

结果写成数据质量报告：

```markdown
# 数据质量报告

- 输入范围与校验值：
- schema / 规则版本：
- 总记录数：
- 有效记录数：
- 缺失 / 重复 / 乱序 / 非法数量：
- 是否允许继续计算：
- 当前无法判断：
```

## 0.3.6 小型检查案例

观察下面三条事件：

```text
sequence=101 time=09:00:00.100 price=100.00 qty=2
sequence=102 time=09:00:00.090 price=100.01 qty=1
sequence=104 time=09:00:00.120 price=100.02 qty=-1
```

至少有三个独立问题：第二条事件时间比第一条早；序号 103 缺失；第三条数量为负。程序不能把它们合并成一句“数据异常”后继续使用结果，也不能因为时间倒退就自动断言 sequence 错误。

## 0.3.7 本章练习

1. **基础题：** 为一条 JSON 行情标出 raw、field 和 domain 三层。
2. **基础题：** 把秒、毫秒和纳秒时间戳分别写成带单位的字段名。
3. **组合题：** 为缺字段、非法小数、重复序号、序号缺口和时间倒退分别定义错误及是否继续。
4. **工程题：** 为十条人工事件写数据质量报告，明确哪些问题能从样本证明，哪些需要查询协议文档。

本章完成标准：不会把“可以解析”当成“可以交易”，并能说明时间、单位与数据版本。

## 0.3.8 离开本章前：更新预备项目

- **本章新增：** 结构化输入规格和数据质量报告。
- **本章修改的领域契约：** bytes、文本、结构字段和领域值分层，时间与数值必须带单位。
- **本章新增的正常路径：** JSON/CSV 字段经格式与业务校验后进入汇总。
- **本章新增的边界/故障：** 缺字段、非法小数、重复、gap、时间倒退和损坏输入。
- **一键演示结果：** 对十条人工事件输出有效/无效计数和继续/拒绝决定。
- **保留证据：** raw 样本、字段规格、错误位置和数据质量报告。
- **从此淘汰：** 把“能解析”当成“可使用”，或根据数值大小猜测时间单位。
- **当前仍不能证明：** 规则来自真实交易所，也没有建立真实账本。
