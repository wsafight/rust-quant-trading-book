# 第 22 章 做市、执行、仓位与硬风控

做市策略持续给出买卖报价，希望赚取价差，但也会承担单边成交和价格不利变化的风险。系统必须区分两种权力：策略回答“想下什么单”，独立硬风控回答“最多允许什么单”。即使策略出错，也不能绕过仓位、金额、价格和行情新鲜度限制。

> **学习导航**
>
> - 开始前：理解市场、执行、账本、行情和订单状态。
> - 这一章学会：让策略提出交易想法，再由独立风控决定最多能做多少。
> - 大约需要：14–20 小时。
> - 做完留下：双边报价、最坏风险计算、对冲实验和故障演练。

> **开章场景：双边报价只成交了一边**
>
> 策略同时挂出 100 元买单和 101 元卖单，希望赚取价差。随后市场下跌，买单连续成交，卖单却无人接受，仓位从 0 变成 5、10、15。策略仍认为价格会回来，但账户正在承受越来越大的单边风险，几张尚未确认的买单还可能继续成交。
>
> 策略负责提出交易意图，独立的硬风控还要把当前仓位、活动订单、未知订单和行情新鲜度一起算进最坏情况。**本章要解决的是：怎样从公允价生成报价，同时用不可绕过的限额、减仓和停止机制控制风险。**

> **第一次阅读建议**
>
> 先读 22.1 至 22.10，并一直追问：“如果所有尚未成交或尚未确认的买单突然同时成交，仓位会变成多少？”先理解报价怎样受仓位影响、风控怎样独立拦截；复杂参数校准和组合风险可以第二次再读。

## 22.1 一次报价怎样形成又怎样得到反馈

```text
可信市场状态 -> 估计一个报价参考价 -> 提出买卖报价 -> 独立硬风控
      ^                                        |             |
      |                                        v             v
市场状态变化 <- 成交后价格与盈亏 <- 成交 <- 订单状态 -> 拒绝或缩小订单
                                         |
                                         v
                                    仓位 -> 对冲规则
```

输入、决定和结果都要带时间与版本。策略使用的订单簿、信号、仓位和限额，必须组成一份时间关系明确的决策快照，不能把不同时间点的数据随意拼在一起。

## 22.2 公允价不是“真实价格”

公允价（fair value）是策略此刻用来计算报价的参考估计，不是市场中客观存在的“真实价格”。一个容易解释的估计过程可以从买卖中间价开始，再逐步加入：

- 根据买卖档位数量估计的微观价格，或多档买卖力量差异。
- 短期主动成交与订单流压力。
- 其他交易所当前真正可以成交的参考价格。
- 资金费、期现价差与对冲市场价格。
- 行情过期和订单延迟带来的调整。

每项输入都要说明：它变大意味着价格更可能向哪边走，预测多长时间，多久更新一次，缺失时怎么办。没有可信成交模型之前，不要急着叠加复杂机器学习；更准确地预测中间价，并不保证挂单策略真正赚钱，因为订单可能只在预测失败时成交。

## 22.3 从参考价到买卖报价

策略先根据仓位等因素调整公允价，得到报价中心；再分别向下和向上留出一段距离，形成买价和卖价。这段单边距离常叫半价差（half-spread）：

```text
报价中心 = 公允价
          - 仓位偏移
          - 资金费或期现价差调整

半价差 = 预期交易费用
        + 价格波动补偿
        + 不利成交补偿
        + 系统延迟补偿
        + 对冲成本
        + 安全余量

买价 = 报价中心 - 半价差
卖价 = 报价中心 + 半价差
```

这些组成部分未必能被完全精确估计，但分开写能迫使团队说明收益和风险来自哪里。买卖价格转换到交易所合法价格时，要分别规定舍入方向，确保只挂单报价不会意外立即成交，买卖价也不会互相交叉。

## 22.4 已有仓位怎样改变下一次报价

仓位偏移（inventory skew）用于让报价帮助仓位回到目标附近。当策略已经持有较多多头仓位时，通常降低报价中心或缩小买单数量，让新增买入变得不积极，同时让卖单更容易成交。一个简单线性形式是：

```text
仓位偏移 = 调整强度 k *（当前仓位 - 目标仓位）
```

但这条直线公式只是起点，还要考虑：

- 接近限额时非线性加速。
- 同时调整买卖价格和买卖数量。
- 当前波动、订单簿深度与对冲能力。
- 多个产品共同形成的方向风险。
- 状态未知订单与买卖两边同时成交的可能。

必须始终满足一条规则：多头仓位越接近硬上限，策略不能让买侧变得更容易增加风险。即使组合中存在对冲，也必须拿出明确证据并再次通过独立硬风控。

## 22.5 一张报价从创建到结束

一次报价经历：

```text
计算报价 -> 风控允许或缩小 -> 发送 -> 接受确认并进入活动状态
-> 保留、修改或请求撤销 -> 成交、撤销、拒绝或状态未知
```

更新报价太频繁，会不断失去排队位置、增加请求成本，也会增加撤单与成交交错以及触发限流的概率；更新太慢，又会把旧价格留在市场。刷新阈值应根据以下观察调整：

- 公允价变化和报价已经存在多久。
- 大致排队位置与成交概率。
- 成交后一段时间价格向有利或不利方向移动多少。
- 下单、撤单网络往返时间和拒单情况。
- 剩余请求额度。
- 仓位和对冲延迟。

## 22.7 按所有买单同时成交计算最坏风险

最坏风险（worst-case exposure）不能只看已经确认的仓位。计算多头上界时，要假设所有可能增加多头的活动买单和未知买单同时成交，而普通卖单一张也没有成交：

```text
最坏多头仓位 = 已确认仓位
               + 活动买单数量
               + 状态未知买单数量
               - 能被交易所明确保证的只减仓卖单数量
```

这里的“明确保证”必须非常谨慎。普通卖单可能开出空头；“只减仓”也会受到持仓模式和并发订单影响。通常把未确认订单按最坏方向计入更安全。

跨交易所做市还要考虑买卖两边同时成交、对冲订单没有成交、两家交易所分别断线，以及抵押资产一起下跌等情况。

## 22.8 成交后何时对冲

对冲（hedge）是用另一笔方向相反或风险相抵的交易，降低已有仓位的价格风险。常见做法包括：

- 每笔成交后立即主动对冲：承担方向风险的时间短，但费用和成交价偏差较高。
- 仓位累计到阈值后批量对冲：重复交易成本较低，但承担风险的时间更长。
- 挂单等待被动对冲：可能得到更好价格，但不一定成交，等待时仍在承担风险。
- 混合策略：正常被动，接近限额或波动上升时主动。

权威账务只根据已经确认的成交更新。预测仓位可以帮助提前作决定，但不能把“预计会成交”当成真实持仓入账。

不存在一个同时让所有指标最优的对冲参数。应并排比较费用、成交价偏差、风险暴露时间、极端仓位和最大回撤，找出不同取舍下的有效方案，而不是只优化平均交易成本。

## 22.9 分级风险响应

风险动作从轻到重通常包括：

1. 缩小订单、降低刷新频率或扩大买卖报价距离。
2. 禁用异常信号或交易所，只保留仍可信的部分。
3. 停止新增风险，只允许经过控制的减仓订单。
4. 撤活动订单并对账。
5. 主动降低仓位或全局停止交易。
6. 人工接管与恢复审批。

触发原因包括行情过期或缺失、私有消息过期、仓位对账差异、保证金不足、亏损或回撤超限、拒单或限流、对冲过慢、队列积压、时钟异常和配置变化。

## 22.10 紧急停止不是一个简单开关

紧急停止机制（kill switch）不是把一个布尔值从 `true` 改成 `false`。它需要一套独立、可审计的执行和恢复流程：

- 独立于策略主循环的高优先级触发路径。
- 权限控制、多级范围和完整审计。
- 停止新单、撤活动单、确认结果与失败升级。
- 撤单失败时持续查询风险，不能假装已经安全。
- 恢复前对账、根因确认和显式审批。

停止范围可以是单个策略、产品、交易所、账户或全局。若系统内的全局停止也失效，还需要人工控制台和交易所侧的备用措施。

## 22.11 成交后怎样判断这笔交易好不好

每笔成交至少记录：

- 作出决定时的参考价、实际报价、成交价及各自时间。
- 订单是挂单成交还是主动成交、费用、报价年龄和排队估计。
- 成交后 10 毫秒、100 毫秒、1 秒和 10 秒的方向调整价格变化（signed markout）。
- 成交前后仓位、对冲延迟和对冲成交价偏差。
- 策略、配置和订单簿版本。

先用账务关系证明总盈亏能够由现金、仓位和费用解释，再把变化拆成彼此不重复的分析项目：赚取价差、持仓重新估值、交易费用、资金费用、对冲成交价偏差和剩余未解释部分。若各项定义会重复计算，就不能用一张漂亮图表替代账本。

## 22.12 策略评审

每个策略都应回答下面六组问题：

- **收益假设**：谁为什么愿意支付这份收益？
- **数据**：作决定时真正能看见什么，数据缺口怎样处理？
- **执行**：怎样模拟订单类型、排队、延迟、费用和市场冲击？
- **风险**：仓位、保证金、交易所、模型和系统故障风险是什么？
- **证据**：未参与调参的数据、敏感性、容量和失败实验说明什么？
- **上线计划**：只观察、测试网和小范围试运行各自要通过什么检查，何时紧急停止？

## 22.13 一次报价的数值推导

假设 BTC 永续合约当前最高买价和最低卖价是 `60,000.0 / 60,001.0`，中间价为 `60,000.5`。短期买卖力量让策略把公允价向上调整 `0.8`，得到 `60,001.3`。

策略当前持有 0.4 BTC 多头，目标仓位为 0。为了减少继续买入，仓位模型把报价中心向下移动 `2.0 USDT`；暂时不考虑资金费和期现价差：

```text
报价中心 = 60,001.3 - 2.0 = 59,999.3
```

从报价中心向买卖两边留出的距离为：

```text
交易费用预期      0.4
价格波动补偿      0.9
不利成交补偿      0.8
系统延迟补偿      0.3
对冲成本          0.5
安全余量          0.3
半价差合计        3.2
```

因此原始买卖报价为 `59,996.1 / 60,002.5`。若最小价格变动是 0.1，这两个价格已经合法。由于当前多头仓位偏高，买价离市场更远，卖价相对更容易成交；数量规则还可以让买单只有 0.05 BTC，卖单为 0.15 BTC。

这些数值只是演示计算过程，不表示参数已经合理。研究还要用历史成交、成交后价格变化和对冲成本调整各项；硬风控则要检查允许价格范围、最小订单价值、仓位、活动订单和行情年龄。若最高买价已经升到 `60,002.5`，原卖单会立即成交；若公允价或订单簿版本已经变化，它也可能只是过期报价。发送前必须使用最新可交易订单簿，再检查“只挂单”规则。

## 22.14 最坏仓位算例

当前已确认多头仓位是 8 个最小数量单位，还有活动买单 4、状态未知买单 3、活动卖单 5，多头上限为 12。不能简单把买卖订单相减：

```text
简单净额 = 8 + 4 + 3 - 5 = 10
```

因为 sell 可能不成交，而买单可能同时成交：

```text
最坏多头仓位 = 8 + 4 + 3 = 15 > 12
```

原因是卖单可能一张也不成交，而所有买单可能同时成交。系统应拒绝新增买单，并考虑撤掉部分活动买单。即使卖单被交易所标记为“只减仓”，是否能抵扣仍要核对持仓模式、订单大小和其他并发减仓单。保守风控通常不会把尚未成交的减险意图当成已经实现的保护。

空头最坏情况也要单独计算。多个产品的组合风险还要考虑它们对共同价格变化的敏感度和压力情景损失，不能只看简单的净币数。

## 22.15 对冲阈值算例

策略每次挂单成交平均增加 0.01 BTC 仓位。每次都立刻主动成交来对冲，固定成本较高，因此考虑累计到 0.05 BTC 再统一对冲。

批量对冲减少了多次支付买卖价差的成本，但持有方向仓位的时间变长。若短期波动估计为每秒 20 个基点，累计过程平均耗时 2 秒，0.05 BTC 在价格 60,000 时价值 3,000 USDT，粗略价格风险尺度为：

```text
3,000 * 20 bps * sqrt(2) ≈ 8.49 USDT
```

这个结果不是精确的风险价值（VaR），只用于说明阈值必须同时比较交易成本和价格风险。波动上升、订单簿变薄、仓位接近限额或对冲交易所变慢时，应更早主动对冲；正常流动性下可以适当增加批量。

研究输出应比较不同阈值下的费用、成交价偏差、对冲延迟、极端仓位和最大回撤，而不是只选择历史净盈亏最高的一个点。

## 22.16 一次成交的会计与分析视图

策略先通过挂单买入 1 单位，成交价 100，费用 0.02；随后以 99.80 主动卖出对冲，费用 0.05。暂不考虑资金费用：

```text
已实现价格盈亏 = 99.80 - 100.00 = -0.20
交易费用       = 0.02 + 0.05 = 0.07
账户权益净变化 = -0.27
```

若买单成交时公允价为 100.10，看起来成交价有 0.10 的优势；但对冲时参考公允价已经跌到 99.85。分析可以把结果解释为最初获得的价格优势、随后不利的市场变化、对冲成交价偏差和费用，但这些项目不能重复计算，而且相加后必须等于 `-0.27`。

如果监控面板把“价格优势 +0.10”和已实现价格盈亏 `-0.20` 直接相加，就可能重复计算同一段价格变化。账务视图先证明资金能够对上，分析视图再解释为什么变化；两者回答不同问题。

## 22.17 本章练习

1. 实现双边报价建议，并测试多头仓位上升时，买单不会变得更容易增加风险。
2. 扩展硬风控，把活动订单和状态未知订单计入最坏风险，并覆盖买卖两边同时成交。
3. 比较立即、批量和被动对冲在三种波动与订单簿深度环境下的结果。
4. 演练对冲交易所断线，写出自动动作、最大风险和恢复检查。

本章完成标准：策略无法直接下单，所有意图都经过独立、可审计的硬风控；任何报价收益都能拆解到费用、成交后价格变化、仓位和对冲成本。

## 22.18 回顾与进入检查点

策略从可解释的公允价开始，根据当前仓位调整报价中心，再向买卖两侧留出足够距离，形成报价建议。但建议不等于下单权。独立硬风控使用行情年龄、价格偏离、单笔和总量限制、已确认仓位、活动订单和状态未知订单计算最坏风险，并留下允许、缩小或拒绝的审计记录。

仓位和对冲也是动态风险问题。立即对冲缩短方向风险时间，却会支付买卖价差和市场冲击；等待批量对冲可以节省成本，却要承受期间的价格变化。对冲规则需要按波动、订单簿深度、交易所状态和资金费用分别评估。紧急停止则是一组带范围、原因、负责人和恢复检查的状态变化，不能由策略自行重置。

现在进入[阶段检查点四](gate-4-trading-loop.md)，用一组可控制的交易所脚本，把行情、适配器、策略、硬风控、订单管理系统和账本连成闭环。检查重点不是正常成交，而是消息顺序异常和程序重启后，风险边界仍然不会被绕过。
