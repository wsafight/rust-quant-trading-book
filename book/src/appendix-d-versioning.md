## 交易规则的有效期

交易所 API、instrument metadata、费率、限频、保证金、订单状态和 reduce-only 语义会变化。本书只讲建模和验证方法，不把示例值作为当前生产规则。任何 adapter 或研究数据集都应同时保存：

- venue、产品和 API 版本；
- 官方页面标题、URL、访问日期和可用的规则生效时间；
- 原始 metadata/响应 fixture 及 checksum；
- 解析器、舍入和 capability 配置版本；
- 规则变化后的迁移测试与回放结果。

网页“今天仍能打开”不证明历史规则未改变。历史回测必须使用事件当时有效的 metadata；生产启动则应校验当前 metadata 与已批准版本，不一致时默认不开放交易。

## 版本策略

- `MAJOR`：章节结构或配套工程契约不兼容，旧学习证据需要迁移。
- `MINOR`：新增章节、检查点、模块或重要规则说明，原主线仍兼容。
- `PATCH`：勘误、链接、措辞或不改变教学契约的小修复。

发布一个版本时保留测试过的 `Cargo.lock`，记录 Rust/mdBook 版本并归档统一检查输出。示例 benchmark 不承诺跨硬件或跨版本得到相同耗时，只要求输入、环境和正确性结果可追踪。
