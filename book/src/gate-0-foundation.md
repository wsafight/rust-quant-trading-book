# 阶段检查点零：独立运行与定位问题

Gate 0 用于判断读者是否具备进入 Rust 与交易系统主线的基础。它不考察复杂代码，而是检查你能否独立运行、观察、修改、诊断并保存证据。

已经有编程经验的读者可以直接尝试本页任务。通过后不需要逐章学习第 0 部分。

## 统一验收场景

准备一个包含 6～10 行简化成交记录的小目录：

```text
learning-check/
├── README.md
├── data/
│   └── fills.csv
├── expected/
│   └── summary.txt
└── notes/
    └── run.md
```

数据至少包含正常买卖、非法方向、非正数量和时间倒退。你可以使用熟悉的语言或手工步骤完成检查；本关不要求 Rust。

## 必做任务

1. 从 README 确认工作目录、输入和预期输出。
2. 统计总记录、有效记录、非法记录、买入数量、卖出数量和最终净数量。
3. 修改一条有效记录，先预测结果，再重新计算。
4. 制造一次错误路径，并从第一条可行动错误开始定位。
5. 写一份数据质量报告，区分格式错误、业务错误和事实不足。
6. 使用 Git 提交输入、规则和最终报告，提交前检查 diff。
7. 让另一位读者仅依据 README 重复结果。

## 自动或机械验收

- 运行入口只有一套明确步骤；
- 相同输入重复执行得到相同摘要；
- 无效方向和非正数量不会进入净数量；
- 输入缺失时明确失败，不生成看似正常的零结果；
- 报告列出输入范围和版本；
- Git diff 中没有 secret、真实账户信息或无关文件。

## 人工演示

在 5 分钟内完成：

1. 说明当前目录和输入文件；
2. 运行或执行汇总步骤；
3. 解释一个正常输入与一个非法输入；
4. 修改数量并预测摘要变化；
5. 展示 Git diff；
6. 说明当前结果不能证明什么。

评审者可以任选一个变化：删除输入文件、把方向改成未知值、让时间倒退，或者插入重复行。读者应先预测错误属于哪一层，再观察实际结果。

## 评分量表

每项 0～2 分，满分 10 分；“运行与路径”或“错误定位”为 0 时不能通过。

| 维度 | 0 分 | 1 分 | 2 分 |
| --- | --- | --- | --- |
| 运行与路径 | 不知道从哪里运行 | 依赖口头提示 | README 足以独立运行 |
| 输入与规则 | 字段含义不清 | 有规则但边界不全 | 输入、单位、非法值和动作明确 |
| 错误定位 | 只会反复尝试 | 能识别大致类别 | 能从第一条证据验证一个假设 |
| 版本与证据 | 只有最终文件 | 有提交但变化混杂 | 提交可解释且含运行记录 |
| 独立复现 | 只有本人能完成 | 他人需询问隐藏步骤 | 他人可按说明复现并改变输入 |

建议达到 8 分以上再进入第 1 章。

## 未通过时怎样回补

| 观察到的问题 | 回到章节 | 回补动作 |
| --- | --- | --- |
| 经常在错误目录运行命令 | 第 0.1 章 | 每次运行前记录当前目录与目标文件 |
| 无法说清输入怎样变成输出 | 第 0.2 章 | 重新画输入、状态、输出和错误四格图 |
| JSON 能读就认为数据正确 | 第 0.3 章 | 分离结构解析与业务校验 |
| 修改丢失或无法说明改了什么 | 第 0.4 章 | 用三次小提交重做预备项目 |
| 别人无法复现 | 第 0.4 章 | 把每个口头提示写进 README |

## 通过证据

- 输入样本与字段说明；
- 汇总结果和数据质量报告；
- 一次失败与修复记录；
- 三次可解释提交；
- 一条来自复现者的反馈及对应文档修订。

通过 Gate 0 只说明你已经具备学习工程课程的基础，不说明你已经掌握 Rust。下一步进入第 1 章，把同一套运行、观察、修改和留证据的方法用于 Rust 项目。
