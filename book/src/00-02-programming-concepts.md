# 第 0.2 章 用通用概念理解程序

编程语言的写法不同，但程序都在做相似的事情：接收输入，按照规则转换状态，产生输出或错误。本章不要求记忆 Rust 语法，先用交易流水建立这些通用概念。

> **学习导航**
>
> - 开始前：能找到文件、运行命令并区分正常输出与错误。
> - 这一章学会：理解值、类型、函数、条件、循环、集合和测试。
> - 大约需要：5–7 小时。
> - 做完留下：一张交易流水汇总表、规则说明和边界案例。

> **本章层级：必学。** 这里只建立语言无关的心智模型，第 2 章会用 Rust 精确表达。

## 0.2.1 值和类型

下面四个值虽然都能写成文本，但含义不同：

```text
buy
100.00
2
2026-01-02T09:00:00Z
```

它们分别表示方向、价格、数量和时间。类型的作用不仅是告诉计算机怎样存储，更是限制哪些操作有意义：价格可以与价格比较，方向不能与数量相加，时间戳不能被误当订单编号。

## 0.2.2 变量是有名字的值

可以把一笔成交写成：

```text
side = buy
price = 100.00
qty = 2
```

名字应表达单位和方向。`x`、`value` 在很短的公式中可能足够，但跨越多个步骤后，`price_ticks`、`qty_lots` 和 `cash_change` 更容易被检查。

## 0.2.3 函数把一条规则隔离出来

函数接收输入并产生输出。例如：

```text
notional(price, qty) = price * qty
```

调用它之前还需要明确：价格和数量是否允许为零或负数，乘法是否可能超过数值范围，结果是什么币种。公式很短，不代表规格完整。

尽量先把规则写成不依赖文件和网络的纯函数。相同输入得到相同输出，测试和调试会容易得多。

## 0.2.4 条件表达分支

处理方向时不能假设所有输入都是买入：

```text
if side is buy:
    position_change = +qty
else if side is sell:
    position_change = -qty
else:
    report invalid side
```

第三个分支很重要。把未知字符串自动当成卖出，会让脏数据悄悄改变仓位。

## 0.2.5 循环处理一组事件

一份成交文件包含多行。程序通常逐行执行同一规则：

```text
position = 0
for each fill:
    validate fill
    update position
```

循环还需要决定错误策略：一行错误时停止整个计算，还是隔离该行并输出质量报告？没有普遍答案，但不能静默跳过。

## 0.2.6 集合保存多个值

- 顺序列表适合保存按时间排列的事件；
- 映射适合根据订单编号查找状态；
- 集合本身不保证数据正确，仍需检查重复、顺序和字段规则。

选择集合前先写访问方式，不要根据名字或熟悉程度决定。第 5 章会系统讨论这些取舍。

## 0.2.7 错误不是一个特殊数字

如果没有价格，返回 `0` 会混淆“缺失”和“价格确实为零”。如果方向非法，自动返回空结果又会丢失原因。程序至少需要区分：

- 合理缺失；
- 输入非法；
- 计算失败；
- 当前事实不足，状态未知。

Rust 的 `Option` 和 `Result` 会在后文把这些区别写进类型。

## 0.2.8 测试是输入、动作和预期结果

最小测试表：

| 输入 | 动作 | 预期 |
| --- | --- | --- |
| buy 2 | 更新仓位 | `+2` |
| sell 1 | 更新仓位 | `-1` |
| unknown 1 | 校验方向 | 明确报错 |
| buy -1 | 校验数量 | 明确报错 |

测试不只用于证明正确，也用于保存曾经失败的最小反例。修复 bug 后把反例留下，未来修改就不容易重新引入同类问题。

## 0.2.9 本章练习

1. **基础题：** 为一笔成交列出方向、价格、数量和时间四个值及其类型。
2. **基础题：** 手算三笔买卖后的最终持仓，并写出每一步状态。
3. **组合题：** 为数量为零、方向未知和缺失价格分别定义处理动作。
4. **工程题：** 设计一张至少含两个正常、两个边界和两个非法输入的测试表，并交给另一位读者检查是否存在未说明的规则。

本章完成标准：能用输入、状态转换、输出和错误解释一个小程序，而不依赖具体编程语言术语。

## 0.2.10 离开本章前：更新预备项目

- **本章新增：** 交易记录字段、校验规则和测试表。
- **本章修改的领域契约：** 输入、状态、输出与错误分开，未知方向和非法数量不能进入计算。
- **本章新增的正常路径：** 逐笔处理买卖并手算最终净持仓。
- **本章新增的边界/故障：** 未知方向、零/负数量、缺失价格和多笔事件顺序。
- **一键演示结果：** 根据同一测试表输出正常汇总与非法记录说明。
- **保留证据：** 手算状态、测试表和另一位读者指出的未说明规则。
- **从此淘汰：** 使用特殊数字代替错误，或静默把未知方向当作卖出。
- **当前仍不能证明：** 文本一定能被正确解析，时间顺序也尚未检查。
