# 附录 N 课程试读与维护

本附录面向自学小组、导师和书稿维护者。书稿是否适合初学者，不能只靠作者阅读自己的文字判断，需要观察不同背景读者在哪里停住、怎样误解，以及能否独立完成任务。

## N.1 试读者分组

至少选择三类读者：

1. 会其他语言但不会 Rust；
2. 会 Rust 或后端，但不懂交易；
3. 有量化研究经验，但不熟悉实时与生产系统。

如果书稿希望服务编程零基础读者，还需要第四组：不了解终端、Git、函数和测试的人。他们先试读第 0 部分，不直接评价第 1 章。

## N.2 每章收集什么

试读记录不只问“是否喜欢”，至少收集：

- 阅读与实践实际耗时；
- 卡住超过 30 分钟的位置；
- 必须询问作者才能继续的隐藏步骤；
- 看懂文字但无法独立实现的任务；
- 对术语、单位、方向或时间的误解；
- 参考提示使用到哪一级；
- 第一次未通过验收的原因；
- 哪个示例让读者错误地扩大了结论。

## N.3 观察而不是代做

第一次试读时，观察者不要立即解释。记录读者：

1. 从哪里寻找入口；
2. 怎样判断下一步；
3. 遇到错误先看什么；
4. 是否理解预期结果；
5. 是否能指出当前实现的限制。

只有读者明确卡住后，才按一级、二级提示逐步提供信息。每个必须口头补充的步骤，都是文档、默认值、示例或错误信息的候选改进。

## N.4 试读记录模板

```markdown
# 试读记录

- 读者背景：
- 章节 / 版本：
- 开始与结束时间：
- 独立完成的产物：
- 第一个卡点：
- 使用的提示层级：
- 错误理解：
- 必须口头补充的信息：
- 检查点得分与失败项：
- 建议改动：
- 改动后复测：
```

## N.5 内容修改的优先级

按影响排序：

1. 会导致资金、状态或研究结论错误的内容；
2. 阻止读者继续的隐藏前置；
3. 多名读者重复发生的误解；
4. 练习无法根据书稿独立完成；
5. 时间估计明显偏离；
6. 术语、导航和表达问题。

不要因为某个主题“很重要”就立即扩写。如果读者能够在现有材料下产出正确证据，新增篇幅可能只会降低主线密度。

## N.6 回归检查

每次重要改稿后检查：

- 目标读者和前置条件是否仍一致；
- 新章节是否进入目录；
- 本地链接和锚点是否有效；
- 术语首次出现是否有中文直觉、英文原词和反例；
- 早期简化是否在后续按计划淘汰；
- 练习、提示和验收是否仍对应正文；
- 时间估计是否包含实践和返工；
- 版本记录是否更新。

## N.7 课程效果指标

不要使用“读完人数”作为唯一指标。更有意义的是：

- Gate 首次通过率与回补章节分布；
- 独立复现成功率；
- 故障注入后能否给出正确风险动作；
- 参考答案打开前的独立尝试比例；
- 项目声明超过证据的频率；
- 三个月后仍能解释和重建的关键产物。

书稿的目标不是让检查点显得容易，而是让失败能够准确指出下一步学习位置。

## N.8 发布前学习者验证门槛

下面的门槛必须由真实读者和真实评审记录满足，作者或自动化工具不能代填，也不能用“模拟读者体验”冒充：

| 门槛 | 最低样本 | 通过条件 | 当前记录 |
| --- | ---: | --- | --- |
| Rust 新手完成第一部分 | 1 人 | 不依赖作者代写，通过检查点一或留下精确回补记录 | 待真实试读 |
| 后端工程师完成交易闭环 | 1 人 | 能解释任意暂停点的远端可能状态与最坏暴露 | 待真实试读 |
| 量化研究者完成第五部分 | 1 人 | 能展示负结果、模型敏感性和阶段决定 | 待真实试读 |
| 最终项目独立复现 | 1 名未参与实现者 | 无口头提示完成运行、故障注入和一项结论复核 | 待真实评审 |

“待真实试读”不是书稿缺页，而是效果尚未获得外部证据。未达到这些门槛前，可以发布为候选版或公开试读版，不应声称课程已经由目标读者验证。

每获得一份记录，就把匿名背景、书稿版本、实际耗时、卡点、修改和复验结果追加到维护日志。不要为了让数据好看而删除未通过记录。

## N.9 维护者发布清单

- [ ] 目录包含所有正文和附录页面。
- [ ] 本地链接与章节锚点有效。
- [ ] 所有代码围栏闭合。
- [ ] 目标读者、毕业声明和学习周期一致。
- [ ] 每章有前置、目标、产物、分层练习和章末行动卡。
- [ ] 每部分有首读、复习、卡住路径和不可退化契约。
- [ ] 每个 gate 有回补、评审和下一阶段输入。
- [ ] 参考解答与当前练习版本一致。
- [ ] 外部规则带来源、访问日期和证据边界。
- [ ] 真实试读与独立评审状态没有被夸大。

静态项目检查可以自动化，学习效果只能通过真实读者观察持续更新。两者都需要，但证据类型不能混写。
