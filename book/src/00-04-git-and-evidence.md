# 第 0.4 章 Git 与可复现学习

学习项目会不断变化。如果无法回答“改了什么、为什么改、修改前后结果怎样”，失败经验就会丢失，后续也难以复现。本章只学习进入第 1 章所需的最小 Git 工作流。

> **学习导航**
>
> - 开始前：能管理文件，理解输入、规则、输出和错误。
> - 这一章学会：查看变化、选择变化、提交证据并保护敏感信息。
> - 大约需要：3–5 小时。
> - 做完留下：包含输入、规则和结果三次提交的预备项目。

> **本章层级：必学。** 分支协作和复杂历史整理可以以后再学。

## 0.4.1 Git 保存的是一组有意义的变化

一个提交应回答：

- 为什么需要这次变化；
- 哪些文件发生了什么改变；
- 怎样验证结果；
- 还有什么限制。

“update”“fix”或“一次提交所有练习”很难帮助未来的自己定位问题。提交不必很大，但必须处于可解释状态。

## 0.4.2 最小工作流

```bash
git status --short
git diff
git add path/to/file
git diff --staged
git commit -m "Describe one completed change"
```

`status` 显示哪些文件变化，`diff` 显示尚未暂存的具体内容，`add` 选择下一次提交包含什么，`diff --staged` 在提交前复查。

不要把“文件已经保存”和“变化已经提交”混为一谈。也不要为了得到干净状态而删除自己不理解的文件。

## 0.4.3 一次只提交一个可解释结果

预备项目可以拆成三次提交：

1. 加入原始输入和来源说明；
2. 加入字段校验与测试表；
3. 加入数据质量报告和已知限制。

如果第三步发现第二步规则错误，先保留能够复现错误的输入，再提交修复。失败过程是证据，不需要伪装成第一次就写对。

## 0.4.4 不要提交秘密或受限数据

提交前检查：

- API key、secret、token 和密码；
- 真实账户编号、余额、订单和个人信息；
- 无权再分发的市场数据；
- 编辑器缓存、大型构建产物和临时日志。

把敏感值移出项目并使用明确占位符。删除最新文件不一定能从 Git 历史删除秘密；一旦误提交，应立即撤销凭据并按安全流程处理。

## 0.4.5 README 是复现入口

最小 README 应包含：

```markdown
# 项目名称

## 目标
这个项目验证什么。

## 输入
输入来自哪里，包含什么，是否为人工样本。

## 运行
从哪个目录执行哪条命令。

## 预期结果
怎样判断成功，怎样观察失败。

## 已知限制
当前不能证明什么。
```

只写“运行 main”不够，因为别人不知道环境、输入、命令和成功标准。

## 0.4.6 本章练习

1. **基础题：** 修改一个文本文件，分别用 `status` 和 `diff` 说明发生了什么。
2. **基础题：** 暂存一个文件后检查 staged diff，确认没有无关或敏感内容。
3. **组合题：** 把预备项目拆成“输入、规则、报告”三个提交，每个提交说明验证方式。
4. **工程题：** 让另一位读者只看 README 找到输入、重复操作并指出一个已知限制；把对方询问的隐藏步骤补回文档。

本章完成标准：能用 Git 和 README 说明一次变化，而不是只在自己的工作目录中保存最终文件。

## 0.4.7 离开本章前：更新预备项目

- **本章新增：** 版本历史、README 和复现入口。
- **本章修改的领域契约：** 输入、规则与结果分别提交，提交前检查 diff，敏感信息不得进入历史。
- **本章新增的正常路径：** 他人按 README 找到输入、执行步骤并得到预期摘要。
- **本章新增的边界/故障：** 未跟踪文件、混入无关修改、secret 和依赖口头说明。
- **一键演示结果：** 从干净目录按单一入口复现，并展示三次可解释提交。
- **保留证据：** 首次复现问题、文档修订和第二次复验结果。
- **从此淘汰：** 只有最终文件、无法说明变化来源或把秘密提交进仓库。
- **当前仍不能证明：** 读者已经掌握 Rust 或真实交易系统。
