# 第 0.1 章 文件、目录与命令行

程序不会凭空运行。它需要一个当前目录、一些输入文件、一条启动命令，并把正常结果或错误写到某个地方。本章先建立这张最小地图。

> **学习导航**
>
> - 开始前：能够使用键盘创建和保存文本文件。
> - 这一章学会：识别路径、当前目录、命令、参数、输出和退出状态。
> - 大约需要：3–5 小时。
> - 做完留下：目录树、命令记录、一次成功运行和两次失败诊断。

> **本章层级：必学。** 如果下面的动作已经可以独立完成，可以直接参加 Gate 0。

## 0.1.1 文件和目录

文件保存文本或程序，目录负责组织文件。路径说明一个文件在哪里：

```text
trade-learning/
├── README.md
├── data/
│   └── fills.csv
└── notes/
    └── first-run.md
```

相对路径 `data/fills.csv` 从当前目录开始寻找；绝对路径从文件系统根部开始。命令显示“文件不存在”时，先确认当前目录和路径，不要立刻修改程序。

目录名和文件名区分大小写的行为可能因操作系统而异。项目中应保持写法一致，避免自己的电脑可以运行、其他环境却失败。

## 0.1.2 当前目录决定相对路径

先观察当前目录和内容：

```bash
pwd
ls
```

`pwd` 回答“我现在在哪里”，`ls` 回答“这里有什么”。进入子目录使用 `cd`，回到上一层使用 `cd ..`。

练习命令前先执行 `pwd`，并把输出写进学习记录。这样未来看到路径错误时，可以知道命令当时从哪里运行。

## 0.1.3 命令、参数和选项

一条命令通常由程序名、选项和参数组成：

```text
cargo run --manifest-path path/to/Cargo.toml
^^^^^ ^^^ ^^^^^^^^^^^^^^^ ^^^^^^^^^^^^^^^^^^
程序  动作      选项             参数
```

空格负责分隔参数。带空格的路径需要由 shell 正确引用。复制命令前先知道它会读写什么，不要执行来源不明或会删除文件的命令。

## 0.1.4 标准输出、标准错误和退出状态

程序可以把正常结果写到标准输出，把诊断信息写到标准错误。除此之外，它还会返回退出状态：通常 `0` 表示命令按自己的定义成功，非零表示失败。

这三者回答不同问题：

| 观察 | 回答的问题 |
| --- | --- |
| 标准输出 | 程序产生了什么结果 |
| 标准错误 | 程序为什么警告或失败 |
| 退出状态 | 自动化流程应继续还是停止 |

“屏幕上打印了东西”不等于运行成功；“没有输出”也不一定表示失败。以后执行格式检查、测试和书稿构建时，都要同时看退出状态和具体信息。

## 0.1.5 从第一条可行动错误开始

同一次失败可能打印几十行。先按以下顺序分类：

1. **命令不存在**：工具是否安装，名字是否拼错？
2. **路径不存在**：当前目录是否正确，文件名是否正确？
3. **权限不足**：程序准备读写哪里？
4. **输入不合法**：错误是否指出字段、行或预期格式？
5. **编译或测试失败**：第一条具体错误指向哪个文件和行？

不要一次同时改变多个地方。每次只验证一个假设，否则即使问题消失，也不知道真正原因。

## 0.1.6 最小环境记录

为每次重要练习保存：

```markdown
# 运行记录

- 日期与时区：
- 操作系统：
- 当前目录：
- 工具版本：
- 输入文件：
- 命令：
- 预期结果：
- 实际结果：
- 已知限制：
```

这不是形式工作。几周后结果变化时，这份记录能帮助你区分代码、输入、版本和环境变化。

## 0.1.7 本章练习

1. **基础题：** 创建 `trade-learning/data` 与 `trade-learning/notes` 两个目录，并画出目录树。
2. **基础题：** 在项目根目录和 `data` 目录分别运行 `pwd`，解释相对路径 `fills.csv` 指向哪里。
3. **组合题：** 分别制造“命令不存在”和“文件不存在”，记录两者错误信息中最先可行动的一行。
4. **工程题：** 写一份运行记录，让另一位读者不询问你就能找到并查看同一个输入文件。

本章完成标准：能区分命令、路径、程序和输入造成的失败，不使用“电脑坏了”概括所有错误。
