# Rust 从入门到量化交易工程师

## 用 Rust 构建正确、可回放、可恢复的交易系统

量化交易工程不是“用 Rust 写一个能下单的脚本”。真正的工作是把不完整、延迟且可能乱序的市场信息，变成受风险约束的订单；再把交易所返回的部分事实，恢复成可以审计的订单、仓位、现金和 PnL。

本书沿一条真实的数据链展开：

```text
交易所行情 -> 本地订单簿 -> 公允价/信号 -> 报价与对冲意图
     ^                                      |
     |                                      v
对账与恢复 <- 仓位/余额/成交 <- 订单状态机 <- 独立硬风控
                         |
                         v
                  PnL、延迟与告警
```

第一次阅读可以先这样理解图中的术语：L2 行情是按价格档汇总的多档买卖报价；订单意图（intent）是策略想做的事；硬风控（hard risk）是策略不能绕过的风险检查；订单管理系统（OMS）根据确认、成交和撤单等证据维护订单状态；账本（ledger）记录资金事实；PnL 表示盈亏。它们的精确定义和易混边界见[术语与公式速查](appendix-a-glossary.md)。

你会先用 Rust 的所有权和类型系统表达事实，再学习订单簿、永续合约和做市，最后把它们连成可确定性回放、能在部分失败下恢复的系统。每章都围绕工程产物，而不是知识点背诵。

> **第一次打开本书？**
>
> 不要先猜自己应该读第几章。打开[学习看板](learning-dashboard.md)，用一分钟选择入口；如果交易术语陌生，再先读[零基础预备课](beginner-primer.md)。

## 阅读和完成训练是两件事

阅读正文后，你应能理解 Rust 类型与所有权为什么适合表达交易状态，行情、订单、成交、仓位和账本怎样相互关联，回测与实盘之间有哪些关键偏差，以及系统为什么必须在超时、断线、乱序和重启后对账。

只有完成必做练习、阶段检查点和贯穿项目，才应把这些理解描述为工程能力。完成训练后，你需要用实际产物证明：

- 能写出不会混淆价格、数量、订单 ID 和币种的 Rust 领域模型。
- 能重建 L2 订单簿，并在增量缺口后停止发布错误行情。
- 能处理 fill-before-ack、cancel/fill race、重复成交和请求超时。
- 能解释做市收益、逆向选择、库存风险、资金费率和对冲成本。
- 能构建含费用、延迟和保守成交假设的事件驱动回测。
- 能用测试、benchmark、profile、对账和故障演练证明系统行为。
- 能让另一位工程师仅依据项目说明复现演示，并复核至少一项结论。

## 一条可选预备路径与六个主线阶段

| 部分 | 章节 | 学习重点 | 阶段产物 |
| --- | --- | --- | --- |
| 可选预备部分 | 0.1-0.4 | 命令行、编程概念、数据、Git | 可重复运行的学习环境与小项目 |
| Rust 语言与工程基础 | 1-8 | 语法、所有权、领域建模、集合、错误、trait、Cargo | 可测试的领域类型与 Rust workspace |
| 实时系统基础 | 9-12 | 订单簿、并发、Tokio 网络、性能测量 | 有界事件管线与订单簿基线 |
| 市场、产品与执行 | 13-17 | 微观结构、订单执行、衍生品、量化数学、账本与对账 | 可手算并可编码验证的交易模型 |
| 构建交易系统 | 18-22 | 行情同步、adapter fixture、OMS、做市与硬风控 | 行情到订单/仓位的完整状态链 |
| 研究与生产 | 23-26 | 回测、仿真校准、统计验证、可靠性与事故响应 | 可复现研究和生产运行证据 |
| 项目与职业路径 | 27-28 | 贯穿项目、分层学习路线、作品集与面试 | 可演示的完整工程项目 |

这里需要区分三种“初学者”：量化交易零基础可以先读交易[零基础预备课](beginner-primer.md)；会其他语言但不会 Rust，可以从第 1 章开始；如果终端、Git、函数、集合和测试也不熟悉，应先完成[第 0 部分](part-0-guide.md)和 [Gate 0](gate-0-foundation.md)。已有 Rust 或后端经验的读者也建议先用练习验证基础，再跳到自己的缺口。

## 怎样开始阅读

如果不确定从哪里开始，先阅读[全书阅读指南](reading-guide.md)。它提供 Rust 初学者、后端工程师、量化研究者和交易系统开发者的不同入口，也解释配套代码、阶段检查点和贯穿案例怎样配合。

顺序阅读时，每章建议完成四个动作：先明确要避免的交易错误，运行并改坏最小例子，完成一个输入或时序变体，最后保存测试、fixture 或报告作为证据。第零部分和前五个主线部分末尾的阶段检查点用于连接多章内容；第六部分以最终项目独立评审收口。未通过时按检查点中的回补表返回对应章节。

时间有限时，不要只读标题后跳到综合项目。先运行一章的练习或检查点：能独立解释不变量、注入故障并复现结果，就继续；只能复述概念，就从该章正文补齐。

## 完成后的能力边界

完成正文、全部必做练习、适用于自己的阶段检查点和贯穿项目，并经过至少一次独立评审后，读者应具备申请初级 Rust 交易系统、量化开发或研究工程岗位的可验证能力。编程零基础读者需要 Gate 0，所有读者都需要主线检查点一至五。这里的“完成”不等于浏览完页面，也不等同于已经具备独立管理真实资金生产系统的经验。

本书不承诺交易盈利，也不把测试网当生产市场。真实资金下的执行校准、跨团队协作、生产值班和事故判断仍需在受监督的工作环境中积累。

## 本书覆盖与不覆盖什么

本书重点训练实时交易系统、执行与风险工程，尤其关注数字资产 L2 行情、交易所适配、OMS、硬风控、账本、事件回放和生产恢复。它提供进入量化研究工程所需的数据时点、成交模型和统计验证基础，但不是完整的概率论、时间序列、机器学习、投资组合优化或期权定价教材。

完成共同主线后，应从[交易系统工程、量化研究工程、执行与风险工程](appendix-j-graduation-tracks.md)中选择一条继续做深。方向选择用于形成足够的岗位深度，不改变全书共同的正确性、可恢复性和证据标准。

开始阅读：[序言：先成为可信赖的工程师](preface.md)，然后进入[全书阅读指南](reading-guide.md)。第一次接触交易系统的读者，接着阅读[零基础预备课](beginner-primer.md)；编程零基础读者再进入[第 0 部分](part-0-guide.md)。
