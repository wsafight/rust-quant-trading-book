## 1. 工程痛点：普通写法为什么会在实盘翻车？

做因子挖掘或参数扫描时，团队常常一口气回测 200 个策略变体，然后挑出 p 值小于 `0.05` 的几个上线。但就算所有策略全是纯随机噪音，测试 200 次也会凭运气冒出大约 10 个“显著”假阳性。因此研究管线必须引入**多重检验校正（如 Benjamini-Hochberg FDR）**来控制假发现率。

但在用 Rust 写统计过滤函数时，如果不懂 IEEE-754 浮点的坑，很容易写出表面能跑、实则暗藏地雷的代码：

1. **对 `f64` 排序直接 `.partial_cmp().unwrap()`**：Rust 故意不给 `f64` 实现 `Ord`，因为 `NaN` 和任何数比大小都没有意义。一旦上游回测因为某天零成交算出一个 `NaN` 的 p 值，`unwrap()` 就会让整条研究流水线直接崩溃；如果用 `unwrap_or(Ordering::Equal)` 糊弄过去，排序结果会静默错乱，把垃圾因子排进“显著名单”。
2. **放行越界概率与无穷大**：上游算错传进来 `p = -0.01`、`p = 1.2` 或 `alpha = f64::INFINITY`，不校验直接代入 BH 阈值 `rank / m * alpha`，会得出荒谬的全员通过或全员拒绝。

在量化算法库里，**数值稳定性边界必须做成显式的 `Result` 入口守卫**：先拦截所有非有限值与越界区间，再用 `f64::total_cmp` 保证排序全序且确定。

pub enum FdrError {
    EmptyInput,
    InvalidAlpha,
    InvalidPValue { index: usize },
}

pub fn benjamini_hochberg(p_values: &[f64], alpha: f64) -> Result<Vec<bool>, FdrError> {
    if p_values.is_empty() {
        return Err(FdrError::EmptyInput);
    }
    if !alpha.is_finite() || alpha <= 0.0 || alpha >= 1.0 {
        return Err(FdrError::InvalidAlpha);
    }

    let mut indexed: Vec<(usize, f64)> = Vec::with_capacity(p_values.len());
    for (idx, &p) in p_values.iter().enumerate() {
        if !p.is_finite() || !(0.0..=1.0).contains(&p) {
            return Err(FdrError::InvalidPValue { index: idx });
        }
        indexed.push((idx, p));
    }

    indexed.sort_by(|a, b| a.1.total_cmp(&b.1).then_with(|| a.0.cmp(&b.0)));

    let m = p_values.len() as f64;
    let mut max_passing_rank: Option<usize> = None;
    for (rank_zero, &(_, p)) in indexed.iter().enumerate() {
        let rank = rank_zero + 1;
        let threshold = (rank as f64 / m) * alpha;
        if p <= threshold {
            max_passing_rank = Some(rank);
        }
    }

    let mut accepted = vec![false; p_values.len()];
    if let Some(cutoff) = max_passing_rank {
        for &(orig_idx, _) in indexed.iter().take(cutoff) {
            accepted[orig_idx] = true;
        }
    }
    Ok(accepted)
}`}

## 4. 工程检查清单

- **永远用“否定合法集合”校验浮点**：写 `!x.is_finite() || !(0.0..=1.0).contains(&x)`，绝不依赖 `x < 0.0 || x > 1.0` 拦截 `NaN`。
- **用 `f64::total_cmp` 取代 `.partial_cmp().unwrap()`**：再叠加原始索引 `then_with` 决胜，让浮点排序既零 panic 又 100% 确定。
- **区分“全不显著”与“输入污染”**：空输入、非有限数、越界 `alpha` 必须返回明确的 `Err`，绝不静默输出全 `false` 掩盖事故。
