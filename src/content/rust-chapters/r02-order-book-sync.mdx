## 1. 工程痛点：普通写法为什么会在实盘翻车？

交易所推送 L2 盘口时，通常先给一份全量快照（Snapshot），再持续推送毫秒级增量变动（Delta）。新手维护本地盘口最容易犯三个致命错误：

1. **用 `HashMap` 存价位，每次查买一卖一都要全表扫描排序**：行情剧烈波动时，延迟飙升，策略看到的永远是几毫秒前的旧盘口。
2. **丢包后硬着头皮继续合并**：网络抖动丢掉第 `105` 号增量包，第 `106` 号包到达时如果只打一条警告日志就继续更新，盘口里会永远残留一笔“幽灵挂单”，策略以为能以 100.00 买到，实际发单瞬间滑点打穿到 100.80。
3. **出现倒挂盘口（买一 ≥ 卖一）还不停机**：交叉盘口意味着本地状态已经严重腐化，此时如果还允许策略读取买一卖一，做市和套利策略会在几百毫秒内疯狂发单亏光本金。

工业级订单簿的铁律是 **Fail-Closed（故障即封闭）**：一旦发现序列号断档或买一 ≥ 卖一，必须立刻把整本盘口标记为作废，强迫上游重新拉取全量快照。

#[derive(Debug, PartialEq, Eq)]
pub enum BookError {
    Invalidated,
    SequenceGap { expected: u64, got: u64 },
    CrossedBook { best_bid: i64, best_ask: i64 },
}

pub struct OrderBook {
    bids: BTreeMap<i64, i64>,
    asks: BTreeMap<i64, i64>,
    last_seq: u64,
    valid: bool,
}

impl OrderBook {
    pub fn apply_delta(
        &mut self,
        seq: u64,
        is_bid: bool,
        price: i64,
        qty: i64,
    ) -> Result<(), BookError> {
        if !self.valid {
            return Err(BookError::Invalidated);
        }
        let expected = self.last_seq + 1;
        if seq != expected {
            self.valid = false;
            return Err(BookError::SequenceGap { expected, got: seq });
        }

        let side = if is_bid { &mut self.bids } else { &mut self.asks };
        if qty == 0 {
            side.remove(&price);
        } else {
            side.insert(price, qty);
        }
        self.last_seq = seq;
        self.verify_not_crossed()?;
        Ok(())
    }

    fn verify_not_crossed(&mut self) -> Result<(), BookError> {
        if let (Some((&best_bid, _)), Some((&best_ask, _))) =
            (self.bids.last_key_value(), self.asks.first_key_value())
        {
            if best_bid >= best_ask {
                self.valid = false;
                return Err(BookError::CrossedBook { best_bid, best_ask });
            }
        }
        Ok(())
    }
}`}

## 4. 工程检查清单

- **用 `BTreeMap` 替代无序哈希表维护价位档**：`last_key_value()` 取买一、`first_key_value()` 取卖一，兼顾有序性与深度扫描效率。
- **数量归零必须彻底 `remove` 档位**：绝不能在盘口中保留 `qty == 0` 的空价位，否则买一/卖一会被空档位污染。
- **断档与倒挂一律触发不可逆作废**：把 `valid = false` 作为硬闸门，只有完整快照（Snapshot）才能重新激活盘口。
