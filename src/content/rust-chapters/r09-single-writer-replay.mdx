## 1. 工程痛点：普通写法为什么会在实盘翻车？

许多初学者设计交易系统时，会自然而然地把订单簿、持仓和 OMS 包进 `Arc<RwLock<EngineState>>`，让行情线程、成交回报线程和风控定时器线程一起抢锁修改。这套做法在实盘和复盘中会带来双重灾难：

1. **竞态与不可复现（Heisenbug）**：同一微秒内，“一笔撤单回报”和“一笔新盘口快照”到达的线程调度顺序完全随机。昨天实盘亏了一笔钱，今天把同样的日志再跑一遍，因为锁竞争顺序变了，Bug 竟然复现不出来。
2. **回放堆排序失真**：离线回放多路事件（行情、回报、定时器）时，如果只按 `ts_ns` 排序，两个时间戳完全相同的事件出队顺序是不确定的；更糟的是，如果上游日志出现时钟倒退（新事件比已处理事件还早）或者重复写入了同一条事件键，普通循环会默默重复记账。

专业量化引擎的解法反直觉却极其优雅：**放弃多线程共享状态锁，采用单写者（Single-Writer）独占所有权**。所有外部 I/O 线程只负责把事件推进有界队列，唯一的主循环按**严格全序键（Total Order Key）**从最小堆依次取出事件并驱动状态机——没有锁竞争，且给定同一份事件流，跑一万次的结果按位完全一致。

#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord)]
pub struct EventKey {
    pub ts_ns: u64,
    pub source_rank: u8,
    pub seq: u64,
}

#[derive(Debug, PartialEq, Eq)]
pub enum ReplayError {
    ClockRegression { last: EventKey, incoming: EventKey },
    DuplicateEventKey(EventKey),
}

pub struct SingleWriterReplayer<E> {
    queue: BinaryHeap<Reverse<(EventKey, E)>>,
    last_dispatched: Option<EventKey>,
}

impl<E: Ord> SingleWriterReplayer<E> {
    pub fn push(&mut self, key: EventKey, event: E) -> Result<(), ReplayError> {
        if let Some(last) = self.last_dispatched {
            if key < last {
                return Err(ReplayError::ClockRegression { last, incoming: key });
            }
            if key == last {
                return Err(ReplayError::DuplicateEventKey(key));
            }
        }
        self.queue.push(Reverse((key, event)));
        Ok(())
    }

    pub fn next_event(&mut self) -> Result<Option<(EventKey, E)>, ReplayError> {
        let Some(Reverse((key, event))) = self.queue.pop() else {
            return Ok(None);
        };
        if let Some(last) = self.last_dispatched {
            if key == last {
                return Err(ReplayError::DuplicateEventKey(key));
            }
            if key < last {
                return Err(ReplayError::ClockRegression { last, incoming: key });
            }
        }
        self.last_dispatched = Some(key);
        Ok(Some((key, event)))
    }
}`}

## 4. 工程检查清单

- **用单写者代替共享锁**：把核心状态（盘口、OMS、风控、账本）收敛到单一所有权线程，靠 Rust `&mut self` 静态消灭数据竞争。
- **定义严格全序键**：时间戳之外必须附带事件源优先级 `source_rank` 和单调序号 `seq`，用 `BinaryHeap<Reverse<...>>` 做确定性归并。
- **对时钟倒退与重复键 Fail-Closed**：一旦检测到 `key <= last_dispatched`，立刻返回错误并停止状态推进，绝不带脏数据继续跑。
