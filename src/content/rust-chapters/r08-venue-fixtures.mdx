## 1. 工程痛点：普通写法为什么会在实盘翻车？

不同交易所的 WebSocket 增量推送长得五花八门：有的用 `"b"` / `"a"` 表示买卖盘，有的用 `"bids"` / `"asks"`；而且为了避开 JSON 数值精度丢失，主流交易所都会把价格和数量编码成**字符串**，例如 `["68420.50", "1.250"]`。

普通脚本最常见的偷懒写法是：先 `s.parse::<f64>()` 转成浮点数，再乘以 `100.0` 四舍五入转整数。这在实盘里至少会埋下三颗雷：

1. **二进制浮点漂移**：`"100.15"` 经过 `f64` 再乘 `100.0`，在部分边界值上会变成 `10014.999999999998`，直接强转 `as i64` 就少了一跳（1 tick）。
2. **静默截断超精度脏数据**：假如标的最小变动价位是 `0.01`（2 位小数），交易所协议升级或配置错位突然推来了 `"100.155"`。`round()` 会悄悄把它吞掉变成 `10016`，你的盘口和交易所真实撮合价从此偏离半跳。
3. **动态数组越界与缺字段**：如果把一档盘口反序列化成 `Vec<String>`，当交易所推来残缺的 `["68420.50"]` 或多塞了订单计数 `["68420.50", "1.250", "3"]` 时，下标索引要么 `panic`，要么静默忽略协议变更。

正确的工程防线只有一条：**协议层与领域层彻底隔离**——用 `serde` 严格卡住外层字段结构，再通过**字符级定点解析**把字符串直接映射到整数刻度，全程不碰 `f64`，遇到任何非零多余小数立刻拒收。

拿到 `[price_str, qty_str]` 之后，绝不能交给 `f64`。我们直接按字节扫描 ASCII 数字，把整数部分和小数部分按 `scale`（例如 2 位小数对应 `0.01`）累加进 `i64`：

  title="零浮点字符级定点解析器：拒收非零多余小数"

  code={`#[derive(Debug, PartialEq, Eq)]
pub enum ParseTickError {
    EmptyOrInvalidChar,
    PrecisionExceeded,
    Overflow,
}

pub fn parse_fixed_ticks(raw: &str, scale: u8) -> Result<i64, ParseTickError> {
    let s = raw.trim();
    if s.is_empty() || s.starts_with('-') {
        return Err(ParseTickError::EmptyOrInvalidChar);
    }
    let (int_part, frac_part) = s.split_once('.').unwrap_or((s, ""));
    let mut acc: i64 = 0;

    for b in int_part.bytes() {
        if !b.is_ascii_digit() {
            return Err(ParseTickError::EmptyOrInvalidChar);
        }
        acc = acc
            .checked_mul(10)
            .and_then(|v| v.checked_add((b - b'0') as i64))
            .ok_or(ParseTickError::Overflow)?;
    }

    let frac_bytes = frac_part.as_bytes();
    for i in 0..(scale as usize) {
        let digit = match frac_bytes.get(i) {
            Some(&b) if b.is_ascii_digit() => (b - b'0') as i64,
            Some(_) => return Err(ParseTickError::EmptyOrInvalidChar),
            None => 0,
        };
        acc = acc
            .checked_mul(10)
            .and_then(|v| v.checked_add(digit))
            .ok_or(ParseTickError::Overflow)?;
    }

    if frac_bytes.len() > scale as usize {
        for &b in &frac_bytes[scale as usize..] {
            if !b.is_ascii_digit() {
                return Err(ParseTickError::EmptyOrInvalidChar);
            }
            if b != b'0' {
                return Err(ParseTickError::PrecisionExceeded);
            }
        }
    }
    Ok(acc)
}`}

在工程落地上，把每家交易所的真实报文（正常增量、尾随零、精度超限、缺字段、空盘口）固化为**离线固定样本集（Fixtures）**，每次修改协议层都用同一批样本回归验证，就能在不连实盘网络的情况下锁死兼容性。

## 4. 工程检查清单

- **协议层绝不泄漏到核心引擎**：用 `#[serde(rename)]` 和 `#[serde(deny_unknown_fields)]` 把交易所字段命名差异与协议变更拦截在最外层。
- **解析全程零 `f64`**：价格与数量字符串直接按字节流转成定点整数刻度，配合 `checked_mul` / `checked_add` 防止溢出回绕。
- **尾随零宽容、非零超精度零容忍**：把各类真实与畸形报文沉淀为离线固定样本回归集，避免依赖实盘环境肉眼排错。
