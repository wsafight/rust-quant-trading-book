## 1. 工程痛点：普通写法为什么会在实盘翻车？

几乎所有“回测年化 200%、实盘第一天就亏钱”的策略，罪魁祸首都是撮合模拟器过于乐观，犯了三个典型错误：

1. **一触价就默认全额成交（Touch 幻想）**：你在买一价 100.00 挂了 10 手限价单，其实你前面已经排着 500 手别人的单子。市场上刚刚成交了 1 手 100.00，简陋回测器就欢天喜地给你算成交了——实际在实盘里，你根本没轮到队头。
2. **忽略单调时钟，允许“未来数据穿越”**：历史日志里偶尔夹杂乱序时间戳，如果撮合器不强制检验时间单调递增，策略就会用未来的成交价给过去的挂单撮合，造出惊人的虚假收益。
3. **非确定性撮合导致 Bug 无法复现**：用随机 UUID 或系统当前时间给成交回报编号，跑两次回测结果都不一样，排查策略缺陷如同大海捞针。

真正靠谱的离线撮合器，必须支持按需切换保守/激进成交假设（`Touch`、`TradeThrough`、`L2Queue`），并且做到**同一份输入流跑 100 次，输出 100% 比特级一致**。

  code={`use std::sync::atomic::{AtomicU64, Ordering};

#[derive(Debug, Clone, Copy)]
pub enum FillModel {
    Touch,
    TradeThrough,
    L2Queue { queue_ahead: u64 },
}

pub struct RestingBuyOrder {
    pub limit_price: i64,
    pub remaining_qty: u64,
    pub model: FillModel,
}

pub struct SimMatcher {
    last_ts_ns: u64,
    next_fill_id: AtomicU64,
}

impl SimMatcher {
    pub fn on_market_trade(
        &mut self,
        ts_ns: u64,
        trade_price: i64,
        trade_qty: u64,
        order: &mut RestingBuyOrder,
    ) -> Result<Option<(u64, u64)>, &'static str> {
        if ts_ns < self.last_ts_ns {
            return Err("non-monotonic clock detected");
        }
        self.last_ts_ns = ts_ns;

        let filled_qty = match &mut order.model {
            FillModel::Touch if trade_price <= order.limit_price => {
                order.remaining_qty.min(trade_qty)
            }
            FillModel::TradeThrough if trade_price < order.limit_price => {
                order.remaining_qty.min(trade_qty)
            }
            FillModel::L2Queue { queue_ahead } if trade_price < order.limit_price => {
                *queue_ahead = 0;
                order.remaining_qty.min(trade_qty)
            }
            FillModel::L2Queue { queue_ahead } if trade_price == order.limit_price => {
                let overflow = trade_qty.saturating_sub(*queue_ahead);
                *queue_ahead = queue_ahead.saturating_sub(trade_qty);
                order.remaining_qty.min(overflow)
            }
            _ => 0,
        };

        if filled_qty == 0 {
            return Ok(None);
        }
        order.remaining_qty -= filled_qty;
        let fill_id = self.next_fill_id.fetch_add(1, Ordering::Relaxed);
        Ok(Some((fill_id, filled_qty)))
    }
}`}

## 4. 工程检查清单

- **回测必须做多模型压力对比**：策略至少要通过 `L2Queue` 或 `TradeThrough` 验证，只在 `Touch` 下盈利的策略禁止上实盘。
- **所有队列扣减使用 `saturating_sub`**：防止无符号整数下溢崩溃或回绕。
- **拒绝外部系统时钟与随机数**：撮合器只认事件自带的单调时间戳，用确定性自增 ID 保证 100% 可复现。
