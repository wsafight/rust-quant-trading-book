## 1. 工程痛点：普通写法为什么会在实盘翻车？

组合优化与衍生品定价模块是策略资金分配的“大管家”，但常见写法经常因为维度错位和数学奇点把整个组合带偏：

1. **切片维度不匹配与运行时越界**：用 `Vec<f64>` 传 4 个标的的波动率，却和 5 个标的的目标权重数组混用；或者传入一个空切片导致权重求和为 `0`，算出全 `NaN` 权重直接把账户仓位清空。
2. **返回匿名元组 `(f64, f64, f64, f64)` 导致 Greeks 拿反**：Black-Scholes 算完返回 `(price, delta, gamma, vega)`，调用方一不留神解构成 `(price, gamma, delta, vega)`，拿 Gamma 当 Delta 去对冲，一秒钟就把中性组合对冲成巨额方向敞口。
3. **到期时间 `t <= 0` 或波动率 `sigma <= 0` 触发除零**：临近交割日算出的剩余时间可能是 `0.0` 甚至因时钟误差出现 `-1e-6`，直接丢进 `sigma * t.sqrt()` 立刻炸出 `NaN` 或 `Infinity`。

Rust 的 **`const N: usize` 常量泛型** 能把“输入 N 个资产、输出严格 N 个权重”焊死在编译期；而 **`bool::then_some` + 具名 `Greeks` 结构体** 则能把数学奇点与字段混淆一次清零。

        return None;

            weights[i] = inv[i] / sum;
        }

pub struct OptionGreeks {
    pub delta: f64,
    pub gamma: f64,
    pub vega: f64,
}

fn std_norm_pdf(x: f64) -> f64 {
    (-0.5 * x * x).exp() / (2.0 * std::f64::consts::PI).sqrt()
}

fn std_norm_cdf(x: f64) -> f64 {
    // Abramowitz & Stegun 近似或误差函数实现，保证 [0, 1] 单调有界
    0.5 * (1.0 + (x / std::f64::consts::SQRT_2).tanh())
}

pub fn call_greeks(spot: f64, strike: f64, rate: f64, vol: f64, time_yr: f64) -> Option<OptionGreeks> {
    let valid = spot.is_finite()
        && strike.is_finite()
        && rate.is_finite()
        && vol.is_finite()
        && time_yr.is_finite()
        && spot > 0.0
        && strike > 0.0
        && vol > 0.0
        && time_yr > 0.0;

    valid.then_some(())?;

    let sqrt_t = time_yr.sqrt();
    let d1 = ((spot / strike).ln() + (rate + 0.5 * vol * vol) * time_yr) / (vol * sqrt_t);
    let pdf = std_norm_pdf(d1);

    Some(OptionGreeks {
        delta: std_norm_cdf(d1),
        gamma: pdf / (spot * vol * sqrt_t),
        vega: spot * pdf * sqrt_t,
    })
}`}

## 4. 工程检查清单

- **固定资产篮子优先用 `<const N: usize>`**：让编译器静态核对输入与输出维度一致，同时获得栈上零堆分配性能。
- **用 `valid.then_some(())?;` 或 `bool::then(|| ...)` 收口数学边界**：严防非正到期时间、零波动率或 `NaN` 进入 `ln`、`sqrt` 和分母。
- **杜绝多值浮点匿名元组**：期权 Greeks、风险指标一律封装为具名结构体，靠字段名消除对冲接错线的低级事故。
