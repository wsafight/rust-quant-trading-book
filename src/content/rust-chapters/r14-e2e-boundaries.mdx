## 1. 工程痛点：普通写法为什么会在实盘翻车？

前面 13 章，我们把整数刻度、L2 订单簿、双式账本、OMS 状态机、独立硬风控、单写者回放、有界背压与算法守卫逐一拆解打磨完毕。但很多团队在把各个模块拼成完整系统时，依然会在最后一步功亏一篑：

1. **模块彼此互相持有可变引用，演变成一团意大利面**：策略直接改账本、OMS 直接调发单网络、风控偷偷读未经校准的本地缓存。任何一处小改动都会牵一发而动全身，且根本无法脱离实盘网络做端到端确定性演练。
2. **只测“风和日丽”的快乐路径，从未测过极端边界与重启恢复**：平时模拟成交都正常，直到实盘某天闪退重启——程序开机既没拉取交易所挂单，也没对比账本持仓，更没锁住重启闸门，直接按空仓重新开仓，10 秒内把账户仓位翻倍。

真正的工业级量化内核必须做到两点：**全链路数据流严格单向编排**（每个模块只做纯输入输出变换），以及**开机默认处于 `Reconciling`（对账锁定态），对账核验通过前绝不放行任何新订单**。

    RejectedByRisk,
    OrderRouted(u64),
    NoSignal,

pub struct TradingKernel<B, S, R, O, L> {
    pub mode: SystemMode,
    book: B,
    strategy: S,
    risk: R,
    oms: O,
    ledger: L,
}

impl<B, S, R, O, L> TradingKernel<B, S, R, O, L> {
    pub fn new(book: B, strategy: S, risk: R, oms: O, ledger: L) -> Self {
        Self {
            mode: SystemMode::Reconciling,
            book,
            strategy,
            risk,
            oms,
            ledger,
        }
    }

    pub fn complete_reconciliation(&mut self, positions_match: bool, open_orders_synced: bool) {
        if positions_match && open_orders_synced {
            self.mode = SystemMode::LiveTrading;
        } else {
            self.mode = SystemMode::Halted;
        }

    pub fn guard_live_entry(&self) -> Result<(), StepOutcome> {
        match self.mode {
            SystemMode::LiveTrading => Ok(()),
            other => Err(StepOutcome::BlockedByMode(other)),
        }
    }

把全书 R01–R14 串起来，一套经得起实盘考验的量化系统，必须离线回归覆盖以下 **17 类核心不变量边界**（分四大防线）：

- **数据与账本防线（5 类）**：① 价格/数量零浮点精度漂移 ② 非零多余小数拒收 ③ L2 序列断档与交叉盘口整本失效 ④ 多空反手均价与已实现盈亏精确守恒 ⑤ 重复成交回报幂等去重。
- **执行与风控防线（5 类）**：⑥ 拆单 `PendingCancel` 持续占住父单容量 ⑦ 成交早于确认的 OMS 乱序吸收 ⑧ 终态绝不回退 ⑨ 本地 `timeout` 强制转 `Uncertain` 并计入最坏敞口 ⑩ 行情过期或 Kill Switch 触发时全量 Fail-Closed 拒单。
- **并发与数值防线（4 类）**：⑪ 单写者全序键归并零竞态 ⑫ 时钟倒退与重复事件键立即中止 ⑬ 有界通道满载背压不 OOM ⑭ `NaN` / `Infinity` / 除零 / 越界概率在算法入口全部拦截。
- **故障与恢复防线（3 类）**：⑮ 断网重连强制快照重同步 ⑯ 闪退重启默认锁定 `Reconciling` 等待持仓与挂单双对账 ⑰ 全链路离线事件流跑两遍按位 100% 一致。

## 4. 工程检查清单

- **数据流坚持单向无环编排**：`协议解码 → 全序回放 → 盘口 → 策略/算法 → 硬风控 → OMS → 路由/撮合 → 双式账本`，每层只依赖上一层的确定性输出。
- **重启默认 Fail-Closed**：系统启动恒定进入 `Reconciling` 态，必须通过“持仓一致 + 挂单同步”双核验才能解锁 `LiveTrading`，否则直接 `Halted`。
- **把 17 类实盘边界做成离线回归铁律**：任何策略迭代或协议修改，都必须在离线确定性闭环里跑通全部极端故障场景后再谈实盘上线。
