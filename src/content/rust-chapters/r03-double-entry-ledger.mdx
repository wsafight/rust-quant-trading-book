## 1. 工程痛点：普通写法为什么会在实盘翻车？

成交回报（Fill）是整个交易系统里最值钱的数据流，也是最容易算糊涂的地方。实盘里常见的账本崩坏场景有三类：

1. **网络重传导致重复记账**：交易所断线重连后，经常会把同一笔 `fill_id` 重新推送一次。如果没有幂等去重，账本会记两遍成交，持仓凭空翻倍，风控和策略全线错乱。
2. **多空直接反手（Flip）时均价算错**：当前持有 `+10` 手多单（均价 100），突然成交一笔 `-15` 手卖单（价格 102）。很多新手直接用加权平均公式套上去，结果把平仓盈亏和新开空仓的成本混成一团烂账——正确做法必须拆成“先平掉 `+10` 手并结算已实现盈亏，再以 `102` 为成本新开 `-5` 手空单”。
3. **只改内存余额、不留不可变流水**：一旦盘后对账差了 1 块钱，如果账本只有覆盖更新后的最终数字，根本无从回溯到底是哪笔手续费还是哪次反手算错了。

pub struct PositionLedger {
    net_qty: i64,
    avg_cost_ticks: i64,
    cash_ticks: i128,
    realized_pnl: i128,
    applied_fills: HashMap<u64, LedgerEntry>,
    journal: Vec<LedgerEntry>,
}

impl PositionLedger {
    pub fn apply_fill(&mut self, fill: FillEvent) -> Result<Option<LedgerEntry>, &'static str> {
        if self.applied_fills.contains_key(&fill.fill_id) {
            return Ok(None);
        }
        let closing_qty = if self.net_qty.signum() * fill.signed_qty.signum() < 0 {
            self.net_qty.abs().min(fill.signed_qty.abs())

            0

        let pnl_per_lot = i128::from(fill.price_ticks - self.avg_cost_ticks);
        let gross_pnl = pnl_per_lot
            .checked_mul(i128::from(closing_qty) * i128::from(self.net_qty.signum()))
            .ok_or("pnl overflow")?;
        let realized = gross_pnl.checked_sub(fill.fee_ticks).ok_or("fee overflow")?;

        let new_qty = self.net_qty.checked_add(fill.signed_qty).ok_or("qty overflow")?;
        if new_qty == 0 {
            self.avg_cost_ticks = 0;
        } else if self.net_qty == 0 || self.net_qty.signum() != new_qty.signum() {
            self.avg_cost_ticks = fill.price_ticks;
        } else if closing_qty == 0 {
            let old_val = i128::from(self.net_qty.abs()) * i128::from(self.avg_cost_ticks);
            let add_val = i128::from(fill.signed_qty.abs()) * i128::from(fill.price_ticks);
            self.avg_cost_ticks = ((old_val + add_val) / i128::from(new_qty.abs())) as i64;

        let trade_cash = i128::from(-fill.signed_qty)
            .checked_mul(i128::from(fill.price_ticks))

        self.realized_pnl = self.realized_pnl.checked_add(realized).ok_or("total pnl overflow")?;

        let entry = LedgerEntry { fill_id: fill.fill_id, cash_delta: trade_cash, realized_pnl: realized };
        self.applied_fills.insert(fill.fill_id, entry);
        self.journal.push(entry);
        Ok(Some(entry))
    }
}`}

## 4. 工程检查清单

- **幂等键先于一切计算**：任何成交回报进入账本的第一行代码必须是 `fill_id` 去重检查，杜绝重放翻倍。
- **反手必须拆成“平旧仓 + 开新仓”**：先按旧均价结清 `min(|old|, |fill|)` 的已实现盈亏，再把异号剩余仓位的均价重置为新成交价。
- **状态与流水双轨校验**：内存余额和 `journal` 追加流水同步写入，盘后可随时通过重放 `journal` 做 100% 零误差核账。
